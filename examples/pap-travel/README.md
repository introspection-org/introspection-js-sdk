# Flight Sector · PAP travel

A [Personal Agent Protocol](https://personalagentprotocol.org/docs/0.3/spec) (draft 0.3) demo. Sam's flight QF74 is delayed six hours. Sam asks Atlas, their own assistant, to get them to Sydney in time. Atlas finds Flight Sector, talks with Flight Sector's agent, has Sam sign in once, and rebooks Sam: on UA863 at no extra cost, or on QF8 via Dallas for $400 more once Sam approves the exact terms.

The page is the one [`aauth-travel`](../aauth-travel) shows, from the shared [`travel-demo-ui`](../travel-demo-ui): Sam's chat with Atlas on a phone, what happens behind the chat at each turn (the requests and the conversation between the two agents, as Flight Sector sees it), and every request Atlas makes, with credentials shortened and its Session header decoded.

## The flow

| Sam                                       | What happens on the wire                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| "My QF74 to Sydney is delayed six hours…" | Atlas fetches Flight Sector's `/.well-known/poppy.json` (version `0.3`, its `organization.domain` the host that served it), finds the issuer from the domain's `/.well-known/oauth-protected-resource`, and checks that the issuer's metadata lists `https://{domain}` in `protected_resources`. It opens a **conversation signed out**: no token request, just a new `sid` in a `Poppy-Session` header, signed for that one request by a delegated key that a key in Atlas's `jwks_uri` vouches for. Flight Sector's agent shares QF74's new times, then needs Sam's booking: an `authorization` event, `insufficient_scope`, `bookings:read bookings:write`. |
| Signs in at Flight Sector                 | **Direct Sign-In**, plain OAuth: the authorization code grant with PKCE on Flight Sector's own page, where Sam allows "See your bookings" and "Change your bookings". Atlas exchanges the code with its client assertion (`aud` the issuer) and gets an ordinary refresh token and access token. The token endpoint never sees the Session.                                                                                                                                                                                                                                                                                                                    |
| —                                         | Atlas continues the same conversation, now with the Session header and the access token (`ath` in the Session JWT covers it). Flight Sector finds booking FS-8Q2M and offers UA863 (no extra cost) or QF8 via Dallas ($400 more).                                                                                                                                                                                                                                                                                                                                                                                                                              |
| "UA863, please."                          | Flight Sector checks `bookings:write` and rebooks. Nothing else needs approving.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| "QF8 via Dallas, please."                 | **Operations v2**, in the conversation: Flight Sector doesn't rebook. Its reply carries an operation in `extensions.operations.operation` (`operation_id`, `revision`, the `summary` and `terms`, `expires_at`). Atlas checks the terms against what it asked for and shows Sam the summary in its own interface.                                                                                                                                                                                                                                                                                                                                              |
| Approves                                  | Atlas sends a message with `extensions.operations.approval` naming the operation and revision. Flight Sector checks it is a revision this conversation returned and still current, rebooks, and remembers it did: the same message again gets its original response, and a new message with the same approval adds nothing.                                                                                                                                                                                                                                                                                                                                    |
| Disconnect                                | Atlas closes the conversation and revokes the refresh token (with the access tokens issued under it). The Session carries on signed out: reading the conversation now gets a `401` challenge for `bookings:read`.                                                                                                                                                                                                                                                                                                                                                                                                                                              |

## Run it

Both parties are https hosts: Atlas at `https://atlas.localhost`, Flight Sector at `https://pap.flightsector.localhost` (its domain, OAuth issuer and conversation API). One Next.js process serves both through [portless](https://github.com/vercel-labs/portless), whose proxy needs port 443 (`sudo npx portless proxy start` once, if it doesn't start by itself).

```bash
pnpm install
pnpm --filter introspection-example-pap-travel dev   # open https://atlas.localhost
```

`ATLAS_URL` and `COMPANY_URL` move either party to another https origin.

`pnpm e2e`, with the dev server running, drives the story as Sam would on the page and checks each request: discovery, requests refused without a valid Session header, the signed-out and signed-in conversation, both rebookings, an approval sent twice that books once, and sign-out.

## What is real, and what is scripted

The protocol is real: discovery and its domain and issuer checks; agent identity by Client ID Metadata Document, with `private_key_jwt` assertions addressed to the issuer, each with `iat` and a unique `jti`; Session JWTs signed per request by a delegated key, verified with their delegation, `aud`, `htm`/`htu`, `iat` window, replay cache and `ath`; Sessions keyed by `client_id` and `sid`; the authorization code flow with PKCE and `iss`; company-defined scopes with descriptions and hints, enforced by the agent; conversation ownership, retry-safe message IDs, cursors, `wait`, handoff and close; operations with signed revisions, expiry and at-most-once execution; and revocation.

The agents are scripted, so the demo runs the same way every time: Atlas understands only this story, and Flight Sector's agent answers from a fixed booking. Flight Sector keeps everything in memory, and Sam is already signed in to Flight Sector's site. The page also shows Flight Sector's booking record, which no Personal Agent could see, so you can watch it change once. Mediated Sign-In, Device Sign-In, browser join, Direct Conversations and streaming are not part of the demo, and DPoP-bound access tokens are not offered: the Session JWT binds each request.

## Compared with `aauth-travel`

|                     | `pap-travel`                                                            | `aauth-travel`                                        |
| ------------------- | ----------------------------------------------------------------------- | ----------------------------------------------------- |
| Whose agent         | Sam's own assistant, at Flight Sector                                   | Flight Sector's agent, acting for Sam                 |
| Who vouches for Sam | Atlas names a pseudonymous User ID; Sam signs in to Flight Sector       | Acme's Person Server                                  |
| Permission          | Sam grants Flight Sector's scopes once                                  | Dana approves the trip, with a budget                 |
| The $400 option     | Sam approves the exact terms (Operations v2), and it books once         | Goes back to Dana, against what is left of the budget |
| Each request        | A `Poppy-Session` JWT for its method and URL, covering the access token | An RFC 9421 signature over the request, body included |
| The conversation    | Part of the protocol                                                    | The recipe's own Slack channel                        |
